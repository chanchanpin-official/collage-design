# 素材与交接

## 搜图与拼贴

使用宿主网页／图片搜索准备素材，再导入所选平台排版；搜图独立于 Canva／Figma 图库。

优先使用获准的自有照片，再按对象、场景、器物、活动和纹理检索。搜索词应抽象为公开主题词。

核对原图和来源页，记录作者、可用范围及资产位置；缩略图和下载成功本身不足以核实素材。

按 [选材与层次判断](composition-decisions.md) 记录素材角色、选用理由、色彩处理与同源关系。[视觉示例](visual-examples.md) 用于理解构图，新任务应重新判断素材适用性。

构图处理应保留主体事实；库存或生成图片不能作为真实团队、产品功能或项目实景的证据。

## Codex 图像模型调用

在 Codex 中可调用当前内置图像生成／编辑工具。加载可用的 `imagegen` skill，按实际 schema 操作；模型和参数以宿主能力为准。

1. 根据任务制作主视觉、纹理、概念背景或局部编辑；仅实拍或原像素要求优先。
2. 编辑前查看输入，区分目标与参考，并明确需保留的主体和允许变动的区域。
3. 主视觉预留文字空间，正式文案使用 Canva／Figma 原生文本。
4. 检查主题、层次、真实细节及文字区域，保存选用结果后导入已选平台。
5. 素材清单区分 `real`、`generated`、`generative_edit`，记录来源、输入输出关系与工具实际返回的信息。

内置路线无需另配 API key。不可用时说明缺项；CLI／API 替代路线需用户明确选择，并遵循图像工具指南。图像处理完成后仍在已选平台排版、保存和返修。其他宿主按实际能力处理。

## 任务目录

每次任务在私有项目目录保存必要记录，与公开 skill 分开：

| 文件／记录 | 最少内容 |
| --- | --- |
| brief.md | 目标、用途、尺寸／发布位、所选平台、分层文案与优先级 |
| assets.json | 原始来源页、资源位置、图片角色、可用范围记录、选用状态、平台 asset ID |
| design-state.json | platform（canva／figma）、platform_locked、对应路线、目标链接与 ID、母版、页／Frame／关键文字对象映射、颜色角色及色值、当前阶段 |
| handoff.md | 最新保存结果、人工修改需保留的内容、检查结论、输出文件、具体待办 |

交接以在线最新稿为准，记录实际保存状态；旧对象映射使用前重新核对。长期记录不存凭据、签名上传地址或临时事务。

素材溯源留在交接资料中，画面只包含设计需要的内容。原始需求、对话、生成提示词和个人偏好留在私有任务目录，不回写公开包。
