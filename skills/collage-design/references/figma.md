# Figma 路线

执行前加载当前 `figma-use` 指南；创建文件、构建完整页面时，再按工具要求加载相应技能。使用当前环境的实际 schema，不把普通 Plugin API 的全部能力当作远程 connector 均支持。

适用于 `platform: figma`、`platform_locked: true` 的任务。接收独立准备的素材，在 Figma 内完成制作、保存和返修。

## 连接与账号前置

先完成 [连接与账号核验](connector-preflight.md)。用官方 MCP 的 `whoami` 读取授权账号、可用 plan／团队及席位信息，并向用户同步；不要等权限报错后才核对身份，也不要用网页登录状态代替。

已有文件用当前只读工具核对访问和目标页面；plan／席位本身不证明具体文件可写。新建文件按当前创建指南选择 plan：沿用本任务已指定的目标，只有一个可用项时使用它，有多个且未指定时请用户选择。所需工具未发现时按宿主的工具发现方式查找，不转用 Computer Use。

## 文件与素材

1. 复用前置检查中的身份、目标及访问结果，再读取所需页面、Frame 与既有文字样式。
2. 按当前工具核对制作能力；首次实际写入成功后更新状态，读取成功不代表已验证写入权限。
3. 海报、易拉宝、社媒图优先使用 Design 文件；一张物料一个 Frame，同系列在一个文件组织。
4. 用 `upload_assets` 取得上传入口，把共享素材工序产出的拼贴背景和独立前景写入指定文件，并应用已确定的主题色。按当次工具返回的格式发送文件字节；不要让 `use_figma` 从互联网抓图片，不使用不受支持的图像上传 API。

## 制作与返修

在 `use_figma` 中建立或复制原生文字与图形对象；已有母版优先复制，保留分组与实际分框。图片作为独立素材图层，文字独立可编辑。拼贴层可自由定位；相互对齐、垂直排列的正文组按当前指南组织，避免内容变长后重叠。

修改文字先读取并加载对象当前字体，等待成功后再改文本及排版；字体不可用时明确报告，不悄悄替换。返回实际创建／变更的节点 ID，用于定位和交接。

每次调用明确目标页面和 Frame，不依赖上一次调用的隐含状态。失败后先根据返回结果确认是否已有部分写入，再决定重试，避免重复生成节点。

完成后回读目标节点并查看画面，检查文字溢出、换行、层级、图层遮挡和页面边界；有实际修改后再复查受影响画面。返修只处理目标节点，不重建整个页面。

实体物料把 cm 目标与画布单位映射保存在任务记录中；导出后核对文件物理页面尺寸，不能把 Figma 数值直接当作 cm。
